# Performance Budget

Homeric's reason to exist is large-document performance. Numbers here are the contract.

## Test fixtures

All fixtures are generated by `tools/corpus/generate.dart`. They are deterministic given a seed and use English Latin-script prose drawn from public-domain sources (Project Gutenberg). Block distribution roughly matches a long-form draft: ~85% paragraphs, ~10% lists, ~3% headings, ~2% block quotes.

| Fixture | Words | Blocks (approx) | Use |
|---|---|---|---|
| `tiny.md` | 1,000 | 7 | Smoke tests |
| `small.md` | 10,000 | 70 | Day-to-day dev |
| `medium.md` | 50,000 | 350 | PR perf gate |
| `large.md` | 100,000 | 700 | The primary target |
| `xl.md` | 500,000 | 3,500 | Stress test |

## Target metrics (post-Phase 2)

Measured on Alvaro's MacBook Pro M5 Max, Flutter `stable` channel, release build.

| Metric | Fixture | Phase 1 baseline (expected) | Phase 2 target | Phase 5 target |
|---|---|---|---|---|
| Time to first frame | `large.md` | > 5 s | < 500 ms | < 200 ms |
| Cold-load p95 frame time | `large.md` | > 1000 ms | < 50 ms | < 16 ms |
| Scroll p50 frame time | `large.md` | > 50 ms | < 16 ms | < 8 ms |
| Scroll p95 frame time | `large.md` | > 200 ms | < 33 ms | < 16 ms |
| Active widget count | `large.md` | ~10,000+ | < 500 | < 500 |
| Cumulative `Paragraph.layout()` time (5 s scroll) | `large.md` | TBD | < 200 ms | < 100 ms |

## Regression policy

A PR that touches `packages/homeric/lib/src/core/**`, `packages/homeric_text_layout/**`, or the virtualization layer (when it exists) automatically runs the benchmark suite via `.github/workflows/benchmark.yaml`. A regression of more than **5%** on any p95 metric blocks merge unless the PR explicitly accepts it and updates this document's baseline.

## How to measure locally

```bash
melos run benchmark               # writes to benchmarks/results/<timestamp>.json
melos run benchmark-baseline      # overwrites benchmarks/baseline.json
```

Baselines are committed to the repo so CI can diff against them.
