# Performance Budget

Homeric's reason to exist is large-document performance. Numbers here are the
contract. The current profile route is the real `HomericEditableDocument`
playground; `benchmarks/baseline.json` retains the pre-viewport comparison.

## Test fixtures

All fixtures are generated by `tools/corpus/generate.dart`. They use a
repository-owned versioned PRNG, literal seeds, exact word targets, and
committed byte hashes. The prose is synthetic English Latin-script text from a
small in-repository lexicon; it is not Project Gutenberg material. Block
distribution roughly matches a long-form draft: ~85% paragraphs, ~7% lists,
~5% headings, and ~3% block quotes.

| Fixture | Words | Blocks (approx) | Use |
|---|---|---|---|
| `tiny.md` | 1,000 | 7 | Smoke tests |
| `small.md` | 10,000 | 70 | Day-to-day dev |
| `medium.md` | 50,000 | 350 | PR perf gate |
| `large.md` | 100,000 | 700 | The primary target |
| `xl.md` | 500,000 | 3,500 | Stress test |

## Target metrics

Measured on Alvaro's MacBook Pro M5 Max, Flutter `stable` channel, release build. For reference, non-virtualized Flutter editors (which lay out every block per frame) sit far outside all of these on `large.md`.

| Metric | Fixture | v1 target | Stretch target |
|---|---|---|---|
| Time to first frame | `large.md` | < 500 ms | < 200 ms |
| Cold-load p95 frame time | `large.md` | < 50 ms | < 16 ms |
| Scroll p50 frame time | `large.md` | < 16 ms | < 8 ms |
| Scroll p95 frame time | `large.md` | < 33 ms | < 16 ms |
| Active widget count | `large.md` | < 500 | < 500 |
| Cumulative `Paragraph.layout()` time (5 s scroll) | `large.md` | < 200 ms | < 100 ms |

## Regression policy

The benchmark suite currently runs locally; GitHub Actions remain deliberately
disabled for this phase. A regression of more than **5%** on any p95 metric
blocks acceptance unless the change explicitly updates the baseline with a
performance rationale. The median of three paired disabled-versus-instrumented
p95 deltas above 5% on the 100k fixture invalidates the run as noisy rather
than proving a product regression.

## How to measure locally

Run `melos run benchmark` on macOS. It records profile `FrameTiming`, mounted
row counts, and cumulative engine paragraph-layout counts/time for the real
playground editor. Results are local and ignored; the accepted summary lives
under `benchmarks/`.
